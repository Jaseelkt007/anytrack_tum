## Cleaning rules applied by `clean_investor_csv.py`

- Rows with empty `Name` or `Typ` are dropped (none in current data).
- All string fields are stripped of leading/trailing whitespace.
- `Branche` and `Stage` are split on commas, trimmed, joined with `|` for safe CSV roundtrip.
- LinkedIn URL → `linkedin_slug` extracted from `linkedin.com/in/<slug>` pattern, lowercased.
- Twitter URL → bare handle extracted. Handles unusual paths like `twitter.com/<handle>/status/<id>?s=20` by taking the first path segment; lowercased; validated against `^[A-Za-z0-9_]{1,20}$`. One row in the source data (Michael Grinich, source row 128) had this format and was correctly normalized.
- `country` blank → kept blank in CSV; rendered as `None` by the loader.

## Sanity queries to run after `load_investor_reference.py`

Open Neo4j Browser and run these. Each maps to an M2 acceptance criterion:

```cypher
// 1. Total reference Persons
MATCH (p:Person)-[:WATCHED_BY {tier:'reference'}]->(:User {id:'demo'})
RETURN count(p) AS total;
// expected: 1000

// 2. Angel count
MATCH (p:Person {investor_type:'Angel'}) RETURN count(p) AS angels;
// expected: 79

// 3. LinkedIn identity count
MATCH (p:Person)-[:HAS_IDENTITY]->(:PlatformIdentity {platform:'linkedin'})
RETURN count(DISTINCT p) AS with_linkedin;
// expected: 133

// 4. Twitter identity count
MATCH (p:Person)-[:HAS_IDENTITY]->(:PlatformIdentity {platform:'twitter'})
RETURN count(DISTINCT p) AS with_twitter;
// expected: 129

// 5. Angels with Twitter (the Phase 2 seed pool)
MATCH (p:Person {investor_type:'Angel'})-[:HAS_IDENTITY]->(:PlatformIdentity {platform:'twitter'})
RETURN count(DISTINCT p) AS angels_with_twitter;
// expected: 76

// 6. Big-VC identity count (sanity: the gap)
MATCH (p:Person {investor_type:'VC - Big fund'})-[:HAS_IDENTITY]->(:PlatformIdentity)
RETURN count(DISTINCT p) AS big_vcs_with_identity;
// expected: 0
```

## Idempotency check

Re-running `load_investor_reference.py` should produce no new nodes or edges:

```cypher
MATCH (n) RETURN count(n) AS before_count;
// run loader again
MATCH (n) RETURN count(n) AS after_count;
// before_count == after_count
```

This works because every write uses `MERGE` on a uniqueness-constrained property (`Person.canonical_id`, `(PlatformIdentity.platform, PlatformIdentity.handle)`, `User.id`), and `canonical_id` is generated deterministically from a stable key (linkedin slug → twitter handle → normalized name+type fallback).
